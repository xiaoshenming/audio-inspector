# DEV-PB2：65 条真实终审候选的批量闭环实测

2026-09-23 在 B2B 服务器隔离目录运行。输入是此前 152 条最终配音视频中筛出的 **65 条候选**（原 A 级 32、B 级 33）；后来补出的 **14 条函数括号读法候选已包含在这 65 条中**，没有重复计数。每条都用最终 MP4、配音源码、源码包、字幕和题目上下文重新走 DEV-PB2 的筛查流程。

## 最终结果

| 口径 | 结果 |
|---|---:|
| 重新完整筛查 | 65/65 |
| 产出新的完整候选 MP4 | **65/65** |
| 新 MP4 的哈希、视频轨、音频轨核验 | **65/65** |

复筛无候选的 40 条中：24 条在首轮局部重配音后得到，7 条经有限复查后得到，9 条由 BatchOps 子节点完整重渲染后得到。其余 25 条全部已有新视频，其中 19 条仍有候选，6 条属于重配相同文字后依旧存在的音频候选；模块没有把它们自动判为正确。

## 流程和稳定性

1. 模块从旧清单制作 65 条隔离输入，重新执行 Qwen ASR、DeepSeek 源码与音频两路审查、函数记号的定向逐字听写，均完成；原候选在本轮全部仍有可复核证据。
2. 为**量化试验**，模块使用自己生成的简短“旧文 → 新文”建议模拟确认，逐条保存原 revision、SHA、问题 ID、修复命令和每轮视频。此模拟不等于真实管理员授权。
3. 有明确字幕时间窗且语速变化不大的，用局部重配音、修订源码包、修正字幕和完整 MP4 合成；若时间窗不唯一、无未烧字幕原片或新句子过长，转由现有 BatchOps Render 控制面提交独立测试任务。子节点使用当时弹性组的最新启动模板 **24**。进入子节点的 **24 条任务都成功返回完整视频和复筛结论**。
4. 复查发现模型有一次返回破损 JSON，模块补了格式错误重试；还补了同一句源码缺漏与函数括号读法的合并修复，以及 `f(x+3)` 等函数参数写法。有限复查有明确轮次上限，不会无限重配音。
5. 模块对 65 个最终候选 MP4 逐条核对回执 SHA 和媒体轨，全部通过。工作期间 B2B 有其他 Render 任务并发；本试验仅使用隔离目录、独立 Render 测试任务和存储前缀，没有修改 152 条原始任务，也没有向客户发送结果。

## 不能从本次推断的结论

线上 152 条复审站的 SQLite 在本轮读取时，`reviews` 与 `review_audit` 均为 **0 条**。因此无法按同事的最终标注计算查准率、真实漏检率或“人工认可的修复率”。这里的 **40/65** 只表示新成片完成且模块复筛无候选；仍需同事核听这 40 条中的抽样，并评审剩余 25 条。
