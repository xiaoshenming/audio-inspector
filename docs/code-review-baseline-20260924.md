## 发现并处理的问题

| 审查发现 | 本轮处理 |
|---|---|
| 两个管理员可能并发提交同一会话，重复计费并覆盖状态 | 会话文件锁；批准后先持久保存 `repairing` 和决定，异常用 `resume` 续跑同一决定。 |
| 字幕变化可能命中旧筛查缓存；未烧字幕原片或源码包可能在确认后被替换 | 字幕 SHA 进入缓存、检查与决定；所有修复资源 SHA 在会话中绑定，源码包中的 `main.py` 与审核源码核对。 |
| 240.x 秒尾部 ASR 丢失、函数旁白字幕无法对齐却显示检查完成 | 覆盖尾段；无法定位的函数旁白明确返回未完成证据，无字幕时按实际时长扫描。 |
| BAD→BAND、减→负可能被模型解释中的“近音”直接过滤 | 按实际类别和文字差异保留强证据候选，增加回归样本。 |
| 子节点或本地补音可能擅自改画幅、音色、语速 | 修复入口要求并继承原 TTS 参数；子节点另继承原渲染规格；缺参数时明确拒绝猜测。 |
| 本机 FFmpeg 无 `subtitles` 滤镜、旧预检还引用老包 | 预检区分筛查和局部修复能力，缺 libass 时返回明确错误；预检入口改为 DEV-PB2。 |
| 交接文档可能误导同事调用现有 `rerender` 修正文案 | 教程标明该接口只收 `reason` 且复用旧源码；需新增权威内容 revision、源码包和正式 TTS 的适配。 |

## 已验证的闭环与边界

在 B2B 隔离目录用真实最终配音视频运行：模块报告缺读向量 a → 人工确认新文 → 按原 TTS 参数重新配音 → 生成完整 MP4 → 复筛 `clean` → 仍等待管理员 → 第二次确认后返回 `release_ready`。新源码、字幕、视频 SHA 与回执核对通过，详细见[真实样本回执](real-152-closure.md)。没有发送客户视频。

这份工程评分**不等于算法漏检率达到 5% 以下**。此前独立审计曾找到旧 clean 组的漏报；本轮修正了明确的过滤和覆盖缺口，但没有新的人工作为真值对全部 152 条重标。机器 `clean` 仍按用户要求作为初筛通过建议，正式发送由 BatchOps 原权限流程决定。Mac 若缺 libass，可在带该滤镜的环境运行局部修复，或选隔离子节点。新版 `worker` 参数继承已由单测验证，正式接入后的子节点联调仍需同事执行。
